02

Goal & progress checklist, by phase

Check items off as you go — each phase tracks its own progress, and the bar at the top of the page tracks everything on this sheet combined.

PH 0Environment & codebase orientationMostly done~2–3 days

Goal: get a working Python 3.12 environment and actually read the context documents the repo's own agent instructions point to, instead of starting to code cold.

0/6

Done when: the OpenSeesPy smoke test prints OK in your real environment, and you could explain the folder structure to someone else without looking it up.

Repo's estimate: not separately timed. Adjusted: 2–3 days part-time.

PH 0.5Independent verification (added — not in the repo's own plan)Not started~1 week

Goal: confirm the "100% complete" Phase 1 claim and the Phase 2/3 "production ready" infrastructure actually do what they say, before anything gets built on top of them or cited in a paper.

0/7

Done when: you can point to a specific hand calculation that matches the code's output, for at least one building — not just a green checkmark in a status doc.

Repo's estimate: none — this phase isn't in the original plan. Adjusted: ~1 week part-time.

PH 1Structural modellingClaims complete~3–5 days

Goal: confirm all 80 parametric RC frame templates (5 heights × 4 frameworks × 4 zones) are genuinely present, distinct from each other in the ways BNBC 2020 requires, and not just 80 copies with different labels.

0/4

Done when: you trust the 80 models enough to spend 8–12 hours of compute on top of them.

Repo's estimate: 5–8 days (README Phase 1). Adjusted: 3–5 days, since PH 0.5 already did the deep verification.

PH 2Ground motions & the real IDA campaignInfra ready — not executed~3 weeks

Goal: run the actual multi-stripe incremental dynamic analysis — 80 buildings × 32–40 records × 16 intensity levels — and end up with a dataset you trust, not just a CSV that exists.

0/7

Done when: ida_results_verified.csv exists, is the right order of magnitude (~40–52k rows), and at least one row-level spot check matches physical intuition.

Repo's estimate: 8–12 hrs compute (local) / 1–3 hrs (cloud) — wall clock only. Adjusted total incl. GM verification, monitoring and QC: ~3 weeks part-time around that compute window.

PH 3ML training on the real datasetCode ready — unexecuted~2 weeks

Goal: actually train LR / RF / XGBoost / ANN on the real IDA output, not the "typical results" placeholder table, and get a model + SHAP explanation you can defend.

0/6

Done when: you have one clearly-best model, a defensible R² (0.90 is the target, not a requirement — see Sheet 01), and a SHAP plot that tells a physically coherent story.

Repo's estimate: 6–7 min base run, 45–60 min with hyperparameter tuning (compute only). Adjusted incl. real iteration and interpretation: ~2 weeks part-time.

PH 4Fragility curves & figuresNot started~2 weeks

Goal: turn the trained model into the 12 fragility curves (4 zones × 3 performance levels) and the full figure/table set the paper needs.

0/6

Done when: all 12 curves are generated, all 9 figures and 5 tables exist at publication resolution.

Repo's estimate: ~1 week (README Phase 7). Adjusted: ~2 weeks, run partly in parallel with Phase 5.

PH 5Framework comparative analysisNot started · overlaps Ph 4~2 weeks

Goal: answer the paper's most novel question — where does the Non-Sway → OMRF → IMRF → SMRF ductility staircase stop paying for itself, per zone and per height.

0/5

Done when: you can state, for a given zone and height, which framework is the rational choice — and defend it with a number, not intuition.

Repo's estimate: 2–3 weeks (README §3.6, PROJECT_STATUS.md). Adjusted: similar, run alongside Phase 4.

PH 6WritingNot started~4 weeks

Goal: a complete 7,000–8,500 word draft, written in the order that's actually easiest — results-adjacent sections first, abstract dead last.

0/8

Done when: every section is drafted, every figure/table is referenced in text, and the reference list has 45–65 entries.

Repo's estimate: 3 weeks (README Phase 8). Adjusted: 4 weeks part-time.

PH 7Review, similarity check & formattingNot started~1 week

Goal: turn a complete draft into a submission-ready manuscript.

0/5

Done when: the manuscript matches the journal's own Instructions for Authors, checked live, not from memory.

Repo's estimate: ~1 week (README Phase 9, partial). Adjusted: same.

PH 8Submission & revisionNot startedongoing

Goal: get through peer review with the paper's credibility intact — which by this point mostly means the honesty built into Phases 0.5 through 3 paying off.

0/4

Done when: accepted — or, if rejected, retargeted to the secondary journal (Structures, Elsevier) with the same manuscript.

Repo's estimate: 4–6 weeks (Buildings, README §2.3 — now faster per 2026 data). Adjusted: submission is quick; total time to acceptance is largely outside your control.

Risk register

The repo's own risk register, plus two risks Sheet 01's read of the documents surfaced directly.

RiskLikelihoodImpactMitigation
Silent demo-mode fallback — missing OpenSeesPy produces a complete-looking but non-physical datasetMediumHighVerify the OpenSeesPy import smoke test in the real execution environment before every campaign run, not just once
OpenSeesPy convergence failures during IDAHighMediumAdaptive time-stepping; classify non-convergence as collapse, don't silently drop rows
Dataset too small after QC (<3,000 rows)Low–MedHighScope already grew to 80 buildings/32–40 GMs — headroom exists; increase scale-factor granularity if needed
Best ML model R² < 0.90MediumMediumTreat 0.90 as aspirational (see Sheet 01); report the honest ceiling with discussion rather than force it
Undetected internal document conflicts (LS threshold, journal metrics) propagate into the paperMediumMediumResolved explicitly in Phase 0.5; keep one authoritative config, not parallel numbers in multiple docs
Real ground-motion records unavailable/access issuesLowLowUse well-validated synthetic GMs as fallback; note explicitly as a limitation if used
Python/package version incompatibilityMediumMediumPin Python 3.12 exactly; document in requirements.txt; don't upgrade mid-campaign
Journal rejects on scope before reviewLowMediumRe-check aims & scope live on mdpi.com before submitting, not from the README's cached description
Compute time exceeds estimateMediumLowTime a pilot first (Phase 2 checklist); fall back to cloud burst if local run stalls
